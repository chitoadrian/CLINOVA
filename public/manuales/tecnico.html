Manual técnico

Arquitectura implementada y límites comprobables en el repositorio.

Arquitectura

La interfaz usa React y TypeScript. La Web guarda en IndexedDB y prepara recursos con Service Worker después de la primera carga. El escritorio usa Tauri con Rust y SQLite. El cliente clínico guarda primero localmente y después envía operaciones autenticadas a la Edge Function clinova-api de Supabase.

Datos y seguridad

SQLite aplica migraciones numeradas 001–007. IndexedDB usa un esquema versionado. Usuarios y pacientes se relacionan con atenciones y elementos clínicos; cada escritura comprueba rol, versión y validaciones. Las contraseñas locales se verifican con PBKDF2-SHA256 y sal. Las cuentas cloud de Supabase Auth son separadas de la sesión local.

El proyecto Supabase CLINOVA tiene ID gcsodpalqwwpsiodeeil. PostgreSQL usa el esquema clinova con roles, members, invitations, records, revisions y receipts. Es una capa de intercambio clínico, no una copia literal de SQLite.

Compilación

Para Web: npm ci, npm run build y npm test. Tauri usa Rust para Windows/Linux. Microsoft C++ Build Tools y Windows SDK son herramientas necesarias para construir el paquete Windows; CLINOVA no está programada en C++.

Alcance de las pruebas

Las pruebas locales cubren migraciones, permisos, CRUD, cola y conflictos simulados. El ensayo de 500 fichas usa IndexedDB simulado y no mide el servidor Supabase. La revisión cruzada con otro grupo requiere evidencia propia. La contabilidad de Wilson permanece local.
